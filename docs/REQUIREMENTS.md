# Requirements

Version 0.1 scope. Supersedes the original "Modbus Capture" proposal (`modbus-capture-claude-proposal.md`); the changes and their reasons are in `PROPOSAL-REVIEW.md`. Priorities: **MUST** (v0.1), **SHOULD** (v0.1 if time allows, else v0.2), **COULD** (later). Milestones M0..M4 are defined in `ARCHITECTURE.md` section 16. The engine requirements (L1..L24, LA1..LA18) live in the `go-modbus-trace` repository; this file only states what the application adds.

## Scope

An engineer opens a packet trace recorded by tcpdump, Wireshark, dumpcap or tshark, tells the application which flows are Modbus/TCP, and gets a timeline of what happened in Modbus terms, breakdowns by device, unit, connection, poll pattern and address, a detail view down to bytes and packets, and exports: MBCAP for replay with `modbusctl`, a timeline as CSV/JSON Lines, and a filtered sub-trace as pcapng.

**Non-goals for v0.1**: live capture of any kind; sending Modbus; writes; a replay server (that is `modbusctl server replay`); decoding register values into engineering units (float, scaling, strings, profiles); a daemon, a browser build or any remote mode (headless use is `mbtracectl`); Modbus/TCP Security (TLS), RTU-over-TCP, Modbus/UDP, serial; decryption; editing traces; multi-user access; cloud services; auto-update; telemetry.

## Programs

| Program | What | Runs on |
|---|---|---|
| `modbus-trace-explorer` | Wails v3 desktop GUI. In-process engine (`go-modbus-trace`), local SQLite analysis cache, no network. | macOS (arm64, amd64), Windows amd64 (MUST) and arm64 (best effort), Linux desktop amd64 and arm64 (no armv7: Wails v3 does not support it) |
| `mbtracectl` (library repository) | The headless CLI on the same engine, for gateways and CI. Not built here; the documentation links to it. | Linux amd64, arm64, armv7; macOS; Windows |

## Requirements

| ID | Pri | M | Requirement |
|---|---|---|---|
| R1 | MUST | M1 | **Open a trace.** File > Open (native dialog), drag and drop onto the window, a path on the command line (`modbus-trace-explorer trace.pcapng`), the OS "open with", and a list of the 10 most recent files. Formats: classic pcap, pcapng, and gzip-compressed forms of both (handled as decompression to the cache directory with a progress bar and a free-space check before it starts). The application never modifies the trace. Several files selected together are one continuous trace, ordered by first packet time (SHOULD). |
| R2 | MUST | M1 | **Import in two steps.** (1) *Scan*: progress in bytes, packets and rate, cancellable; (2) a **Flows** step shows the file summary and the flow table from the library's `Scan` (endpoints, packets, bytes, duration, class Modbus/TCP, TLS or other, Modbus score), with the Modbus-like flows preselected, a field for server ports (prefilled with 502 plus the ports the scan found), and a per-flow "this endpoint is the server" override. When the scan finds Modbus flows on a single server port, one click ("Analyze") proceeds. (3) *Analyze*: progress, cancellable, the choices are remembered for that trace. Actionable errors for: no Modbus found (suggest ports, TLS), TLS (Modbus/TCP Security cannot be decoded), unsupported link type or encapsulation (named), truncated file (opens with a warning), unreadable file. |
| R3 | MUST | M1 | **Analysis cache.** The index lives in the OS cache directory (`os.UserCacheDir()/modbus-trace-explorer/`), one SQLite file per trace fingerprint (size, modification time, SHA-256 of the head, library and schema version). It is disposable: deleting it only costs a re-analysis. Reopening an unchanged trace is immediate. A changed or moved trace is detected and re-analysis is offered; if the trace is missing the overview stays readable and detail and export are disabled with a clear message. Directory 0700, files 0600, a size cap (default 2 GiB, least recently used evicted), "Clear cache" in Settings. Rows hold compact fields and provenance references only (`ARCHITECTURE.md` section 5). |
| R4 | MUST | M1 | **Overview strip.** File name and size, first and last packet time and duration, packets, Modbus connections, devices (server endpoint + unit), transactions, and a quality badge (OK, warnings, problems) that opens the Quality view. Capture facts reachable from it: link types, interfaces, snap length truncation, capture drops reported by pcapng, unsupported traffic counts, SHA-256. |
| R5 | MUST | M1 | **Timeline.** The central table of events in time order, server-side paged and virtualized, columns per `UX.md` (sequence, time, client, server:port, unit, transaction ID, function, summary, latency, status, flag icons). Paired request/response is one row; connection open/close, gaps, resyncs and trace notes are rows of their own kind. Time shown in local time, UTC or relative to the first packet (switchable; exact nanoseconds on hover or in the detail pane). Sort by time (default) or latency. Keyboard navigation (`UX.md`). "Go to time" and "Go to frame" (SHOULD). |
| R6 | MUST | M1 | **Detail pane** for the selected row, tabs: *Summary* (decoded request and response in words), *Request* and *Response* (named fields), *Raw* (hex dump with ASCII of the MBAP header and PDU, bytes highlighted per field when a field is selected), *Packets* (the packets that carried the request and the response: frame number as Wireshark counts it, time, interface, payload range, and a copy button for the Wireshark display filter `frame.number == N`), *Notes* (quality flags, validation warnings, connection and role information, why the transaction is or is not exported to MBCAP). Copy of hex, of field values and of the whole transaction as JSON. Bytes are fetched on demand from the trace, never kept in the index. |
| R7 | MUST | M1 | **Filters.** Server/device, unit, client, connection, function(s), status, class (read, write, other), exceptions only, quality flags, time range, data space + address range, and a text box that is parsed into the same filters (grammar in `UX.md`). Active filters appear as removable chips with the resulting counts; they apply to every view and are the default selection of the exports (R13-R15). Filters never change the analysis. |
| R8 | MUST | M2 | **Devices view.** Server endpoint, then unit: transactions by function and status, clients seen, first and last time, transaction rate, bytes, exceptions, unanswered, latency p50/p95/p99/max. Selecting a row filters the other views. |
| R9 | MUST | M2 | **Conversations view.** Connections with client and server endpoint, epoch, how they opened and closed (SYN, midstream, FIN, RST, end of trace), duration, transactions, bytes, role source and confidence, flags. Selecting one shows its history of actions in the timeline ("what did this client do, in order"); gaps and resyncs are marked on it. |
| R10 | MUST | M2 | **Patterns view** ("poll plans"). Per client, device and unit, the recurring requests: function, address range, count, period (median, min, max, jitter), volatility class (static, slow, noisy) from the share of changed responses, first and last time. Selecting one shows the interval distribution and filters the timeline to it. |
| R11 | MUST | M2 | **Addresses view.** Per device, unit and data space (coils, discrete inputs, holding, input): a coverage map of the address intervals that were read or written (counts, first and last time). Selecting an address or interval shows its **value history** from reads (time, raw word or bit, change markers) with writes marked as events (time, client, value written), as a step chart and a table. Values are loaded lazily from the trace with progress, a cap (default 200,000 points, "load more") and cancel. Display of values: hex, decimal, binary; addresses zero-based as sent on the wire, with a 1-based/reference label as a toggle. The view states that it shows what was observed, not a complete register map. |
| R12 | MUST | M2 | **Quality view.** Every counter of the library (retransmissions, out-of-order, overlap conflicts, gaps, resyncs, snap-length truncation, capture drops, unsupported encapsulations, orphan responses, unanswered requests, ambiguous pairs, invalid PDUs, clock-order anomalies, guessed roles), each with its meaning in one sentence and a "show in timeline" action. |
| R13 | MUST | M3 | **MBCAP export.** A dialog with: scope (everything analyzed, current filters, one device), time window, exceptions on/off (default on), change-only off/on, tick resolution, editable target labels, encoding (binary `.mbcap`, `.mbcap.jsonl`, `.mbcap.csv`). A **live preview from the index** shows the samples that will be written, targets and streams, and exclusions by reason with an explanation each (writes, FC23, vendor functions, unanswered, orphan, ambiguous, uncertain, invalid, truncated, outside selection); options that cannot be previewed exactly (change-only) say "up to". The export runs as a cancellable job that **re-streams the trace through the library** (not from the index), then shows the library's report (counts, warnings such as `stale_after_write`) and offers to save it as JSON. The result is byte-identical to `mbtracectl export mbcap` with the same selection. Native Save dialog, atomic write. |
| R14 | MUST | M3 | **Timeline export** as CSV and JSON Lines, for the current filters or everything, as a cancellable job with progress; identical to the CLI's output for the same selection. |
| R15 | SHOULD | M3 | **Sub-trace export** as pcapng: the packets of the connections in the current selection, optionally clipped to the time window, via the library. The dialog states that it includes writes and vendor functions verbatim. |
| R16 | MUST | M3 | **Replay hand-off.** After an MBCAP export the dialog shows copyable commands: `mbcapctl verify <file>` and `modbusctl server replay --input <file> --listen 127.0.0.1 --port 1502 --before-first absent --missing exception` (and, when the export has several targets, one `--target N --port P` line per target), plus the caveats in one short list (writes are not replayed, only what was read exists, unit collisions). Link to `REPLAY-WORKFLOW.md` of the library. |
| R17 | MUST | M1 | **Desktop only, local only.** No network connections by the application, no daemon, no web build, no updater, no telemetry. CSP `default-src 'self'` in the WebView; fonts and assets bundled. |
| R18 | MUST | M4 | **Portability and build matrix** as in "Programs". Linux GUI builds target GTK4 + WebKitGTK 6.0 (Wails v3 default); a `-tags gtk3` variant only if a required distro lacks it and only while Wails supports it (removed in v3.1). Windows arm64 is best effort: built in CI only if it needs no extra work, never blocking a release (Windows 11 on ARM can run the amd64 build under emulation). |
| R19 | MUST | M1 | **Branding and accessibility** per `BRANDING.md`: dark default plus light theme, tokens only, WCAG AA text contrast, full keyboard navigation of the timeline, views and dialogs, no color-only status, labeled icon buttons. |
| R20 | MUST | M3 | **Settings.** Theme; time display (local, UTC, relative); default server ports; address display (zero-based, with reference-label toggle); cache location (shown), size cap and "Clear cache"; recent files list clear. |
| R21 | MUST | M1 | **Large traces.** A trace of several GB must open. Budgets (proposed; M0 measures and records the real numbers in `ARCHITECTURE.md`): analysis throughput at least 50 MB/s end to end on a laptop; resident memory under 500 MB regardless of trace size; index size at most 25% of the trace size; paging, sorting and filtering of a 10-million-row timeline under 150 ms at the 95th percentile; the UI never holds more than a window of rows plus a prefetch margin. The UI stays responsive during import; results of the first pass are usable before the second finishes (SHOULD). |
| R22 | SHOULD | M2 | **Schemas.** JSON Schema (draft 2020-12) in `docs/schema/` for the application's own DTOs (page requests and rows, detail, view models, job events), validated against real engine output in tests, as in the Explorer. Library types keep their schemas in the library. |
| R23 | MUST | M1 | **Logging and diagnostics.** Structured log to a small rotating file in the application's data directory; never trace content, and at info level no IP addresses or paths. "Copy diagnostics" in About: application, library and Wails versions, OS, and the facts of the open trace without paths or addresses. |
| R24 | COULD | M4 | **Open `.mbcap`** (binary, JSONL, CSV) read-only in the same timeline as a samples view (stream, time, request/response decoded with the library's decoders), to inspect what an export contains. Requires no trace. |
| R25 | SHOULD | M4 | **Distribution, unsigned for now.** No macOS or Windows signing identity exists. SHA-256 checksums, CI build provenance attestations, and install notes for Gatekeeper (ad-hoc signed arm64 bundle; approve in System Settings > Privacy & Security or remove the quarantine attribute) and SmartScreen (More info > Run anyway), as `sunspec-explorer` documents. Linux deb/rpm/AppImage via Wails packaging later. All builds run on runners of the target architecture, without emulation. Revisit signing before wide distribution. |

## Acceptance tests

Test infrastructure: traces built with the library's `trace/tracetest` package (synthetic, deterministic, with ground truth), a few small real fixtures, pinned `mbcapctl` and `modbusctl` binaries, optional `tshark`. No test needs privileges or the network.

| ID | Test |
|---|---|
| A1 | Open a pcap and a pcapng built by `tracetest` (several functions, two clients, two servers, two units); the Flows step preselects the Modbus flows; after Analyze the timeline's transactions equal the ground truth (count, order, fields). |
| A2 | Modbus on ports 1502 and 5021 next to HTTP and DNS noise: the scan classifies the Modbus flows and not the noise; a flow the scan missed can be added by overriding the server endpoint; a TLS flow is classed as not decodable. |
| A3 | Midstream start, retransmission, loss, malformed ADU and a resync: the Quality view equals the library's counters, the timeline shows gap and resync rows, and affected transactions carry their flags. |
| A4 | Scale: a synthetic trace with 1,000,000 transactions (generated, and a 10,000,000-row index test) imports within the R21 budgets; page, sort and filter latencies, resident memory and index size are measured, recorded and compared with the budgets. |
| A5 | Detail pane: for a transaction of every function in the library's coverage matrix the decoded fields are right, the highlighted bytes match the selected field, and the Packets tab frame numbers equal `tshark -r <trace> -Y 'frame.number==N'` payloads (where tshark is installed). |
| A6 | Each filter narrows the timeline correctly and consistently across all views; the text box grammar parses to the same filters; the export dialogs default to the active filters; Reset restores everything. |
| A7 | Devices, Conversations and Patterns numbers equal `mbtracectl summary --json` for the same trace and server ports. |
| A8 | Addresses: a register polled with a scripted value sequence shows exactly that history; a write to it appears as a marked event with the written value; a 1,000,000-point history loads progressively, honors the cap and cancels. |
| A9 | MBCAP export through the engine: output passes the pinned `mbcapctl verify`; the preview's counts equal the report's counts; the file is byte-identical to `mbtracectl export mbcap` for the same selection; the pinned `modbusctl server replay` serves the scripted values (the library's LA10 scenario driven through the application engine). |
| A10 | Timeline and sub-trace export equal the CLI's output; the extracted pcapng reopens in the application and shows the same transactions for the selected connections. |
| A11 | Cache: reopening an unchanged trace does not re-analyze; a modified trace prompts re-analysis; a moved trace gives the overview with detail disabled and a clear message; Clear cache works; directory and file permissions are 0700/0600; the size cap evicts the least recently used. |
| A12 | No network: a lint rule and a `go list -deps` test show no `net/http` or dialing in non-test code; the built frontend references no external URL; on Linux CI the application opens a trace and exports inside a network namespace without any interface. |
| A13 | Hostile files: zero bytes, garbage, truncated at every record boundary of a small trace, wrong link type, a huge length field, a gzip bomb (limited by the free-space check): clear message or partial results, no crash, UI responsive, Cancel works. |
| A14 | Both themes, tokens only (no hard-coded colors outside `tokens.css`), keyboard-only walk through open, filter, select, export; contrast numbers of `BRANDING.md` hold; icon buttons have labels; no state is conveyed by color alone. |
| A15 | Build and start on native runners for macOS arm64 and amd64, Windows amd64 (arm64 best effort), Linux amd64 and arm64; a smoke test opens a fixture and shows the timeline (Linux under a virtual display; macOS and Windows as far as the runners allow). |
| A16 | gzip input: the application decompresses to the cache with progress, refuses when free space is insufficient, and removes the temporary file when the trace is closed. |
| A17 | One Go `Service` contract suite passes against the engine; the TypeScript mock Service returns data that validates against the same DTO schemas, and a fixture exported from the real engine is replayed through the mock in a UI test, so the mock cannot drift from the engine. |
| A18 | The application DTO schemas validate real output (R22); a DTO change not made in the schema fails the build. |

## Open decisions

None blocking. Decided: no live capture, one artifact, separate engine library, CLI-only headless, name Modbus Trace Explorer, unsigned releases. The M0 spike settles the index technology and the virtualization approach with measurements.
